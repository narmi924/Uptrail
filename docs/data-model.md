# Uptrail — data model

The schema has 17 tables in MySQL 8.4 and is owned by Flyway (`src/main/resources/db/migration/V1…V5`). Hibernate only validates it (`spring.jpa.hibernate.ddl-auto=validate`). Diagram: [diagrams/svg/data-model.svg](diagrams/svg/data-model.svg).

## Conventions

- Money is `DECIMAL(12,2)` in SGD and `BigDecimal` in Java.
- Training time is stored in half-day **units** (`1` = half a day, `2` = a full day); pages show days.
- Timestamps are `DATETIME(6)` in UTC; business dates (course dates, "today") use the Asia/Singapore calendar.
- Status and code columns are `VARCHAR` with a `CHECK` constraint listing the allowed values.
- Rows that users change concurrently carry a `version` column for optimistic checks; business writes also lock rows (see [architecture.md](architecture.md#write-protocol)).

## Tables

### Identity and organisation (V1)

| Table | Purpose | Key rules |
| --- | --- | --- |
| `employee` | Staff record: staff number, name, email, department, designation, active flag | `staff_no` unique; deactivation instead of deletion once history exists |
| `user_account` | Sign-in account of an employee: username, BCrypt password hash, enabled flag | one account per employee; `username` unique |
| `user_role` | Roles of an account: `EMPLOYEE`, `MANAGER`, `ADMIN` | a manager always holds `EMPLOYEE` too |
| `approval_assignment` | The approving manager of each employee | one row per employee; not self (`CHECK`); loops are refused by the service |

### Catalogue, calendar and entitlements (V2)

| Table | Purpose | Key rules |
| --- | --- | --- |
| `course_category` | The three categories `INTERNAL`, `EXTERNAL`, `CERTIFICATION` with editable display texts | codes fixed by `CHECK`; seeded by the migration |
| `training_provider` | Providers offered on the form | may be deactivated |
| `course_catalogue` | Common courses offered as shortcuts on the form | internal courses have fee 0 (`CHECK`); applications copy the values, so later edits do not change them |
| `training_calendar_year` | One row per year: `DRAFT` or `CONFIRMED`, source note, who confirmed it | applications with days in a year that is not `CONFIRMED` are refused |
| `public_holiday` | Holiday date, name and source note | `calendar_year` is a generated column with a foreign key to its year |
| `training_account` | Entitled half-day units and budget of one employee for one year | unique per employee and year; amounts never negative; lowered only down to what is already used |

### Applications (V3)

| Table | Purpose | Key rules |
| --- | --- | --- |
| `course_application` | One application: reference number (`CATS-yyyy-nnnnnn`), applicant, approver, category, title, provider, dates and sessions, fee, justification, status, decision and completion fields | statuses `APPLIED`, `UPDATED`, `DELETED`, `APPROVED`, `REJECTED`, `CANCELLED`, `COMPLETED`; end not before start; internal fee 0; a decision needs a reason; `(employee_id, client_request_id)` unique for idempotent submission |
| `application_day` | The counted training days of an application (weekends and holidays excluded), each with its units and session | primary key `(application_id, training_date)`; rebuilt on update |

### Audit and ledger (V4)

| Table | Purpose | Key rules |
| --- | --- | --- |
| `audit_event` | Append-only history of every business change: record type and id, event, actor, state change, reason, JSON snapshot, correlation id | never updated or deleted by the application |
| `training_ledger` | Net changes of an annual account caused by one event: reserved and committed units and amounts, reimbursed amount | `UNIQUE(event_id, account_id)` so an event cannot post twice; entry types `RESERVE`, `UPDATE_RESERVATION`, `COMMIT`, `RELEASE`, `REIMBURSE` |

### Claims, documents and email (V5)

| Table | Purpose | Key rules |
| --- | --- | --- |
| `course_claim` | The single fee claim of a completed application: revision, amount, approver, status, decision, reimbursement reference | unique per application; amount > 0; statuses `SUBMITTED`, `APPROVED`, `REJECTED`, `REIMBURSED`; reimbursement reference unique |
| `claim_document` | Receipt or certificate of one claim revision: storage key, original name, detected content type, size, SHA-256 | unique per claim, revision and type; storage key unique and generated by the server |
| `email_outbox` | Emails written with the business change and sent later by the worker | unique per event, recipient and template; statuses `PENDING`, `SENDING`, `SENT`, `FAILED` |

## Balances come from the ledger

An annual balance is never stored as a running total. It is the account's entitlement and budget minus the sums of its ledger rows:

| Figure | Computed as |
| --- | --- |
| Pending | sum of `reserved_units_delta` / `reserved_amount_delta` |
| Approved | sum of `committed_units_delta` / `committed_amount_delta` |
| Available | entitlement − pending − approved (days and budget separately) |
| Reimbursed | sum of `reimbursed_amount_delta`; shown separately and never deducted again |

Ledger effects of each command:

| Command | Ledger row |
| --- | --- |
| Submit | `RESERVE`: + reserved units per year, + reserved fee in the start year |
| Update | `UPDATE_RESERVATION`: new minus old reservation, per year involved |
| Approve | `COMMIT`: reservation moved to committed |
| Reject, delete | `RELEASE`: − reserved |
| Cancel an approved course | `RELEASE`: − committed |
| Complete | none |
| Claim decisions | none |
| Register a reimbursement | `REIMBURSE`: + reimbursed, on the account of the course's start year |

A course that runs across the new year reserves the units of each year on that year's account; the fee belongs to the year in which the course starts. The administrator's operations page recomputes every balance from the applications and reimbursed claims and compares it with the ledger sums.
